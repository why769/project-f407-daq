
# 面包板五功能联调记录（2026-11-23）

## 一、最终功能与实测数据

| 功能 | 实现 | 实测 |
|---|---|---|
| TDS 采集 | ADC1_IN0（PA0），12 位，采样 71.5 周期 | 自来水 330 ppm |
| 温度采集 | DS18B20 单总线（PA1 + 4.7k 上拉），DWT 微秒延时 | 室温 22.0℃；手捏探头升至 28℃ |
| OLED 显示 | SSD1306，I2C（PB6/PB7），6×8 字库 | 双页面显示正常 |
| 触摸按键 | TTP223（PA2），状态机 + 15ms 去抖 | 短按切页、长按出水 |
| 超标报警 | TDS ≥ 500ppm → PA3 拉低 → 蜂鸣器（VCC=3.3V） | 盐水 >500ppm 响，取出停止 |
| 水泵控制 | PA4 → N-MOSFET，长按运行 3 秒自动停 | 定量出水，无需二次操作 |

## 二、联调中解决的四个真问题

### 1. 水泵一启动，显示屏卡死（电源完整性）

- **现象**：长按开泵后屏冻结在最后一帧，短按无反应；按复位可恢复，再长按又卡。
- **定位**：拔掉水泵后长按不再卡 → 排除代码，锁定电流；改用 5V/2A 适配器给板子供电后卡死消失。
- **根因**：蓝pill 由电脑 USB 供电（限流 500mA），水泵启动瞬间 500mA+ 把 5V 拉低到 MCU 欠压阈值以下，MCU 跑飞。
- **解决**：板子改用 5V/2A 适配器供电（ST-Link 仍接电脑，仅烧录用）。
- **教训**：**带电机/继电器的系统，MCU 与负载必须分开评估供电余量**；USB 口 500mA 是硬上限。

### 2. 长按关泵需要按好几次（触摸信号被干扰）

- **现象**：泵运行时，长按要按多次才有反应。
- **根因**：水泵运行时的电源纹波耦合到触摸输出（PA2），电平抖动使状态机把"长按"误判成"短按"（只切页），因此看不到效果。
- **解决**：
  1. 软件：触摸状态机增加 **15ms 去抖**（电平连续 3 次一致才认可）；
  2. 交互：改为"**长按 → 水泵运行 3 秒自动停止**"，去掉"再按一次关闭"的依赖。
- **教训**：**干扰环境下，交互设计要考虑"按键不可靠"**；能自动完成的操作不要依赖第二次按键。

### 3. I2C 总线锁死（偶发）

- **现象**：一次长按后显示永久停在最后一帧，复位后恢复。
- **根因**：负载开关动作的电压尖峰干扰 I2C，从机把 SDA 拽住不放，主机后续传输全部失败。
- **解决**：增加 **I2C 总线恢复**：连续 3 次传输失败 → `HAL_I2C_DeInit` → SCL/SDA 切成开漏 GPIO → 打 **9 个 SCL 脉冲** 逼从机释放 → 手动产生 STOP → `MX_I2C1_Init()` 重新初始化 → 重发 OLED 初始化。
- **教训**：**I2C 死锁恢复是工程必备**，标准做法就是"9 个时钟 + STOP"。

### 4. 触摸与水泵共用操作入口的耦合

- **改进**：短按=切页，长按=出水，职责分离，演示时一个动作对应一个功能。

## 三、最终交互逻辑

```
上电 → 初始化（I2C 探测 0x78/0x7A → SSD1306 初始化 → 蜂鸣器静音）
主循环（5ms 节拍）：
  ① 触摸状态机（含去抖）：短按切页 / 长按出水并计时
  ② 每 500ms 采一次 TDS → 换算 ppm
  ③ DS18B20 非阻塞两段式：启动 → 760ms 后读取
  ④ 水泵 3 秒自动关闭
  ⑤ TDS ≥ 500ppm → 蜂鸣器报警
  ⑥ 脏标记驱动重绘（省 I2C 带宽）
  ⑦ I2C 连续失败 3 次 → 总线恢复 + 重初始化屏
```
