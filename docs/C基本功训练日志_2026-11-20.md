## 第一轮 · 位运算（40 分钟）

### 位宏默写（3/5 正确）

| 宏 | 写法 | 判定 |
|---|---|---|
| SET_BIT | `((x) |= (1u<<(n)))` | ✅ |
| **CLEAR_BIT** | `((x) &= (1u<<(n)))` | ❌ **缺 `~`** |
| TOGGLE_BIT | `((x) ^= (1u<<(n)))` | ✅ |
| **CHECK_BIT** | `(((x)&(1u<<(u)))!=0)` | ❌ 手误 `u`→`n` |
| GET_BIT | `(((x)>>(n))&1)` | ✅ |

**CLEAR_BIT 的错误分析**（概念错，必须记）：

```c
错：x &= (1u<<n);     // 只保留第 n 位，其他全清零 —— 与"清位"正好相反
对：x &= ~(1u<<n);    // ~ 让掩码变成"只有第 n 位是 0"，其余位原样保留
```

数值验证（x=0xFF，清 bit3）：
```
正确 0xFF & ~0x08 = 0xFF & 0xF7 = 0xF7   （只清掉 bit3）
错误 0xFF &  0x08 = 0x08                 （只剩 bit3，其他 7 位全丢）
```

**原理**：与运算"跟 1 与保留原值、跟 0 与强制清零"，所以掩码必须是"目标位 0、其余位 1"。

### 表达式预测（8/8 全对）

```
0x5A & 0x0F = 0x0A    0x80 >> 3 = 0x10
0x5A | 0x0F = 0x5F    0x0F << 4 = 0xF0
0x5A ^ 0xFF = 0xA5    (1u<<7)|(1u<<0) = 0x81
~0x0F & 0xFF = 0xF0   0xA5 & ~(1u<<2) = 0xA1
```

**关键进步**：每题都先展开二进制再算 → 10.29 那次 `0x80>>2` 的"hex 位数抄错"问题不再出现，**方法有效**。

### 二进制/nibble 展开（5/5 全对）

```
0xA7 = 1010 0111    0xA7 & 0x3C = 0010 0100 = 0x24
0x3C = 0011 1100    0xA7 | 0xF0 = 1111 0111 = 0xF7
0xF0 = 1111 0000
```

## 第二轮 · 指针（40 分钟，3/3 正确）

### swap（正确）

```c
void swap(int *a, int *b)
{
    int c = *a;
    *a = *b;
    *b = c;
}
```
要点：参数是指针、调用传地址、用临时变量中转。

### my_strlen（两版都正确，推荐保留指针相减版）

```c
/* 版本 A（更佳）：指针相减 */
int my_strlen(const char *s)
{
    const char *x = s;
    while (*x != '\0') x++;
    return (int)(x - s);       /* 指针相减 = 元素个数，不是字节数 */
}

/* 版本 B：计数 */
int my_strlen(const char *s)
{
    int x = 0;
    while (*s != '\0') { x++; s++; }
    return x;
}
```
要点：`const char*` 好习惯；指针相减以"指向类型"为单位；`x-s` 类型是 `ptrdiff_t`，赋给 int 建议强转。

### frame_init（正确）

```c
void frame_init(frame_t *f)
{
    f->head    = 0xAA;   /* 补上帧头更完整 */
    f->id      = 0x25;
    f->len     = 3;
    f->data[0] = 0x01;   /* 数组成员不能整体赋值，只能逐元素 */
}
```
要点：`f->id` 与 `(*f).id` 等价，后者括号必须有；结构体传指针才能改到本体。

### sizeof 分析（答对）

`sizeof(frame_t) == 11`，**无填充**。原因：成员全为 `unsigned char`（含数组元素），整体对齐 = 1，任何地址都能放，不需要补空隙。对比 C 阶段 `frame_size.c`（含 `int`，对齐 4），才会出现填充。**判据：先看成员里最大的对齐要求。**
